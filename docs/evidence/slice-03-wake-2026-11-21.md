# Slice 3 wake-word regression

## Acceptance procedure

1. Keep the Pixel foreground, disconnect WAN while preserving the LAN, and start live video from the paired browser. In Voice, set **Wake name** to `Alexa`. The fixed prefix appears beside the input. Confirm that the phone and browser both show Listening.
2. While recording and streaming, say the saved phrase ten times. Wait for the command to finish and for rearm before each attempt. Repeat with at least one command spoken immediately after the phrase and one wake followed by silence. Record the number of wake events, misses, duplicate events and first-word truncations.
3. Say **Hey Google** and **Google** with Alexa configured. Neither should trigger. Mute and repeat the real phrase, then unmute and verify two fresh consecutive wakes. Save another name while the stream is active and repeat the cross-trigger check with the former name.
4. End and restart the stream and repeat the wake. Check that the phone and browser show the same command result and that the finalized recording has audible audio. Capture voice model, processing ratio, drops and queue lag from `adb logcat -d -s LVC`.

## Automated evidence

- Android debug `0.1.0+1`, arm64-v8a, Flutter 3.50.1, sherpa-onnx 2.0.2. Installed on Pixel 10 Pro XL, Android 17 (API 37, build CP4A.261105.040.A1, November 2026 patch), via `adb install -r`.
- `npm run build && npm test` passed 23 dashboard tests. A Chrome 158.0.8127.36 fixture also verified the fixed visible prefix, saved-name hydration and four name updates through the actual WebSocket payload.
- `flutter analyze` passed. `flutter test` passed 80 tests. `./gradlew :app:testDebugUnitTest` passed 22 tests. `flutter build apk --debug --target-platform android-arm64` passed.
- Android instrumentation replayed locally generated Piper US and GB voices through the app’s actual detector and packaged JNI/assets, using 20 ms chunks and rearming between each clip. The first run detected 24 of 24 targets across Robot, Eli, Elrobot, Zorbo, Naviro and Xylobot. Robot also fired on six near-neighbor clips (Robert and Elrobot). The other names had zero false wakes in their 24 negative replays each.
- Follow-up Pixel replay at 17:09 UTC: **Alexa 6/6** with **0/38** false wakes, including four `Hey Google` and two bare `Google` clips. **Google 4/4** with **0/40** false wakes, including six `Hey Alexa` clips. The other six target names again had 24/24 positives. Robot still had 6/40 false wakes on the two similar names, and the other five recognizers had 0/40 each.
- Stricter and competing-pronunciation decoder configurations reduced some Robot false triggers while missing valid Eli, Zorbo or Xylobot clips. The demo build keeps the general name recognizer settings. The owner’s demo criterion is recognition of the selected name and rejection of clearly different names, such as Alexa versus Google.
- The app now uses a dedicated, phrase-constrained keyword spotter. The previous continuous speech recognizer mistranscribed the sample wake phrases before the text matcher could see them. The older KWS integration also shipped active default keywords in its graph. The rebuilt detector dispatches only its configured wake result.
